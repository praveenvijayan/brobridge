Local-first transport · Node / Bun ⇄ Browser

The bridge that only your tab can cross.

brobridge connects a local Node or Bun process to a browser tab. It gives binary speed and a strict trust fence. Every other page in the browser stays out.

Executive summary

Why this layer exists

Many products open a local port so a browser UI can talk to a CLI, an editor, or an agent. That port is reachable from every web page the user visits. Loopback is not a security boundary in a browser, and the WebSocket handshake ignores the same-origin policy.

brobridge is the transport and session layer under your product. It is not an RPC framework — your RPC framework sits on top of it. Your team writes typed application code. Your users open one URL.

“Loopback is not a security boundary.”

Any page can send requests to 127.0.0.1. brobridge refuses those requests with exact-authority Host checks, Origin and Sec-Fetch-Site enforcement, and a one-time launch token that mints a signed session cookie. Each check is written down in the threat model, attack by attack.

For implementers

Implement it, step by step

Follow the steps in order. Each step has one result that you can see. The code blocks are complete — copy them as they are.

01

Install the packages

Make sure that you have Node ≥ 20 or Bun. Install the host package in your process, and the client package in your web app.

npm install brobridge          # host: Node / Bun process
npm install @brobridge/client  # browser: your web app
02

Create the bridge in your host process

The bridge binds 127.0.0.1 on an ephemeral port. expose registers methods. stream registers a stream route. bridge.url carries a one-time token — show it or open it, do not log it. 

// host process
import { createBridge } from 'brobridge';

const bridge = await createBridge();

bridge.expose('demo', { echo: (message: string) => message });

bridge.stream('ticker', async (stream) => {
  const encoder = new TextEncoder();
  for (let tick = 0; ; tick += 1) {
    await stream.write(encoder.encode(`${String(tick)} `)); // backpressure is the await
    await new Promise((resolve) => setTimeout(resolve, 1_000));
  }
});

console.log(`open ${bridge.url}`); // http://127.0.0.1:52341/?bt=<one-time token>

To serve your UI from the bridge itself, pass your built index.html as the index option. Then the page and the bridge share one origin, and no extra configuration is necessary.

03

Connect from the browser

Call connect(location.href) in your page. The client redeems the token one time, keeps the signed cookie, and reconnects with backoff after a drop. 

// browser
import { connect } from '@brobridge/client';

const bridge = await connect(location.href); // burns the token, keeps the cookie

await bridge.call('demo.echo', 'hello'); // 'hello'

for await (const chunk of await bridge.openStream('ticker')) {
  console.log(new TextDecoder().decode(chunk)); // survives a dropped socket
}
04

Make sure that it works

Run the demo. It starts a host and a page, with a button that cuts the socket, so you can see the resume. 

node --experimental-strip-types scripts/demo.ts

If the page is served from a dev server (for example Vite on port 5173), the origins differ. In that case, add the dev origin on the host: 

const bridge = await createBridge({
  allowedOrigins: ['http://localhost:5173'], // only during development
});
05

Tune only when you measure a problem

All options have safe defaults. These are the ones that applications change most.

Security

The rules that keep the fence closed

The defaults are safe. Each rule below prevents one known attack. The full model is in THREAT-MODEL.md, with the check and the package that enforces it.

Do

Show or open bridge.url. Use bridge.origin in logs — it never contains the token.

Do not

Do not write bridge.url to a log file or crash report. The URL carries the one-time launch token.

Do

Validate every argument in your expose handlers. Arguments come from the page and are untrusted input.

Do not

Do not add production origins to allowedOrigins. The option exists for local dev servers only.

Do

Keep the client heartbeatTimeoutMs equal to the value on the host. Different values cause false disconnects.

Caution

Do not set allowNonLoopback: true unless you read docs/non-loopback.md first. A non-loopback bind accepts traffic from the network, and the cookie fence alone does not protect it. There is intentionally no environment variable for this option.

Adapters

Bring your own RPC framework

The raw surface — expose/call with JSON, stream/openStream with bytes — is small on purpose. An adapter earns its place when you want end-to-end types or you already have a router. All three give you the same brobridge underneath.

birpc

@brobridge/adapters/birpc

Plain typed functions in both directions. No schemas, near-zero concepts. Pick this when you start from nothing and want minimal.

oRPC

@brobridge/adapters/orpc

Standard-schema validation (Zod, Valibot, ArkType) and OpenAPI output from the same router. Pick this when you build an API that you validate.

tRPC

@brobridge/adapters/trpc

The biggest ecosystem, plus React Query. Subscriptions map onto brobridge streams and get resume for free. Pick this when a tRPC router exists.

Adapters and the raw surface coexist on one bridge. A common shape: tRPC for the app API, plus one raw stream for the PTY or log firehose. Stay raw when payloads are bytes, or when bundle size is critical. Full comparison: docs/choosing-an-adapter.md.

Failure handling

Branch on identity, not on text

Error identities are stable API. Branch on error.reason (client faults) or error.code (wire faults). Never branch on message text.

BridgeClientError

From @brobridge/client. The fault happened in the browser and never reached the host. Discriminant: reason.

BridgeError

From @brobridge/core, re-exported by the client. A peer expressed the fault on the wire. Discriminant: code.

import { isClientError, SnapshotRequiredError } from '@brobridge/client';

try {
  for await (const chunk of stream) render(chunk);
} catch (error) {
  if (error instanceof SnapshotRequiredError) return refetchAndReopen();
  if (isClientError(error, 'streams-unavailable')) return showDegradedBanner();
  throw error;
}

SnapshotRequiredError

The tab reconnected after sessionTtlMs, so byte-exact resume is not possible. Refetch your state, then open the stream again.

streams-unavailable

The client runs on the HTTP fallback. Unary calls work, streams do not. Show a degraded banner — the socket retries in the background.

A call rejects during a drop

A call in flight when the socket drops rejects, because the host may have executed it. A retry is your decision — make handlers idempotent where you can.

Every error an application can see, with cause and fix: docs/troubleshooting.md.

Before you ship

The seven-point checklist

Complete each point before your first release. Each point maps to a section above.

  1. Origin. Serve the UI through the index option, or remove dev entries from allowedOrigins.
  2. Token hygiene. Make sure that no log line, crash report, or analytics event contains bridge.url.
  3. Input validation. Make sure that every expose handler validates its arguments.
  4. Error branches. Handle SnapshotRequiredError and streams-unavailable in every stream consumer.
  5. Retry policy. Decide, per call, what happens when a call rejects during a socket drop.
  6. Heartbeats. Make sure that the client and host timeout values match.
  7. Loopback. Make sure that allowNonLoopback is absent, or that you completed the non-loopback document.
